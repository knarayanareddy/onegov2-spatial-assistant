# OneGov spatial assistant — review

## Scope and verdict
Implementation, pinned to `9fc8666c6d4a5ae1138d600fcea2b0af92029300`. Runtime NOT RUN. This is a static sample, not an assessment of the complete application or of provincial deployment. The sampled README describes a Dutch drinking-water decision-support tool with three surfaces — [README:3-5](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/README.md#L3-L5) and [README:24-28](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/README.md#L24-L28). Postgres, MLflow, external data, and identity infrastructure are operational dependencies. Actual SQL generation, retrieval behavior, router-level access checks, live SSO wiring, and domain/scientific accuracy were not inspected here.

## Findings ledger
- **OG-1 — High, confirmed static:** [`src/backend/app/auth.py:28-30`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L28-L30) says, “Dev keeps the admin role so single-user moderation works as before.” [`src/backend/app/auth.py:85-87`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L85-L87) then uses the exact fallback branch `if mode != "dev" and settings.AUTH_REQUIRED:` followed by `return _dev_user()`. In JWT/header mode with `AUTH_REQUIRED=false`, missing or invalid credentials therefore collapse to a local admin identity in the sampled helper. Impact still depends on deployment configuration and route dependencies, which were not verified. Fail closed outside explicitly local development and test authorization through real routes.
- **OG-2 — Medium, confirmed static:** [`src/backend/app/main.py:46-56`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/main.py#L46-L56) and [`src/backend/app/main.py:61-71`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/main.py#L61-L71) log fallback instead of surfacing a hard failure: “Failed to enable Postgres FAQ cache; staying in-memory” and “Failed to enable Postgres audit; staying in-memory.” If that branch is reached with durable storage configured, accountability and persistence can degrade despite the intended backend. Make the deployment policy explicit, expose readiness, and test failed initialization and recovery; whether later first-use failures also surface correctly was not verified.
- **OG-3 — Medium, confirmed static:** [`src/backend/app/auth.py:44-52`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L44-L52) sets `audience = settings.AUTH_JWT_AUDIENCE or None` and `options = {"verify_aud": bool(audience)}` before decode. The sampled function therefore disables audience verification when no audience is configured, and no issuer validation is visible in this sampled function. Require an owner-selected issuer and audience for production, then test invalid claims. Token acceptance in a real configuration remains unverified.

[`src/backend/app/auth.py:69-70`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L69-L70) declares `async def get_current_user(request: Request) -> CurrentUser:`. ## Five disciplines
- **Correctness:** session ownership is checked in [`src/backend/app/auth.py:99-103`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L99-L103); its application across routes remains unknown. Water-risk outputs need independent domain calibration, source provenance, and uncertainty review. The README itself says calibration is “explicitly *not* external validation” at [README:151-152](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/README.md#L151-L152).
- **Automation:** the sampled CI covers assumption-source checks, `tests_scenario`, `tests_chatbot`, and a frontend build, not a sampled unit-auth path or observed live SSO/data deployment. The sampled `test_auth.py` call signature is stale against the current dependency signature, but this review did not execute it. Deliberately broken negative controls are required before trusting any added regression gate.
- **DevOps:** compose uses a documented local database password default at [`docker-compose.yml:43`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/docker-compose.yml#L43) and [`docker-compose.yml:75`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/docker-compose.yml#L75). Treat the sampled stack as local only; verify readiness, persistent audit, backups, restoration, and migrations before deployment.
- **OWASP:** header identity trusts configured incoming headers in [`src/backend/app/auth.py:60-66`](https://github.com/knarayanareddy/onegov2-spatial-assistant/blob/9fc8666c6d4a5ae1138d600fcea2b0af92029300/src/backend/app/auth.py#L60-L66); a trusted proxy must strip client-supplied identity headers and block bypass. Inspect SQL/LLM prompt injection, row-level authorization, credential storage, transport, and dependency integrity separately; the sample cannot establish their safety.
- **UI/UX:** map and B1-Dutch chatbot are described in the README. Keyboard, screen reader, map alternatives, source attribution, failed queries and uncertainty presentation were not tested. A build does not prove accessibility.
